Spec — ChildHome Diferenciada por Perfil Etário

Data: 2026-04-02 Sprint: Sprint 2 — Comitê de Product Design Responsável: @agent-ux-missao-da-semana Status: Pronto para avaliação do comitê — não implementar Coautoria técnica: requer validação do Arquiteto (seção de componentes e dados)

Contexto e base para este documento

Este documento especifica a diferenciação de interface da ChildHome para os 4 perfis etários do Blip. A ChildHome atual (src/pages/ChildHome.tsx) usa a mesma estrutura visual para todos os perfis, com apenas variação de cor/gradiente do tema — o problema P0-01 da auditoria UX de 30/03.

Problema central (P0-01): “A tela da criança é visualmente idêntica à do pai. A criança não entende o que deve fazer ao abrir o app. A ação principal está enterrada abaixo de dois cards de métricas que existem para o pai, não para ela.”

O que este documento resolve: - P0-01 — Hierarquia visual diferente por perfil - P1-01 — Estado vazio motivador - P1-02 — Progresso semanal com representação de consistência - P1-06 — Recompensa visível para a criança

Decisão de produto vigente: MVP começa com Pequenino e Aventureiro. Explorador e Pro são especificados aqui para o comitê mas não entram na primeira sprint de implementação.

Base de código existente: - src/lib/childAgeProfile.ts — getAgeProfile(), getThemeTokens(), tokens por tema - src/lib/celebrationUtils.ts — mensagens de celebração por faixa - src/components/Celebration.tsx — componente de celebração (existe, pode ser especializado) - src/components/MonthlyProgressBar.tsx — barra de progresso mensal (existe, pode ser reutilizada para pais) - src/components/WeekDaysAccordion.tsx — accordion de tarefas por dia (existe) - src/components/TaskCard.tsx — card de tarefa individual (existe)

Princípios transversais

Hierarquia de ação por faixa etária

A ChildHome deve responder à pergunta “o que eu faço agora?” imediatamente ao abrir. A ordem dos elementos na tela deve refletir a urgência de ação, não a importância analítica:

Perfil Pergunta central Elemento mais importante
Pequenino “O que tem pra mim hoje?” Tarefa do dia — botão grande
Explorador “Qual missão eu tenho?” Lista de missões ativas
Aventureiro “Quanto XP estou ganhando?” Barra de XP + missões
Pro “O que falta completar hoje?” Lista densa com status

Estrelas de Coragem — isolamento visual (Decisão B1 + B3)

As Estrelas de Coragem são sempre isoladas visualmente da meta semanal. Em nenhum perfil elas aparecem na mesma seção, barra ou card que os pontos de tarefas. Isso não é escolha estética — é requisito pedagógico aprovado pelo Comitê Pedagógico (Montessori + Dweck + Duckworth).

Pequenino Central, frequente, reage 110px
Explorador Presente mas não central 76px
Aventureiro Apenas em metas grandes 56px (notificação)

Decisões de design registradas

Por que não usar o WeekDaysAccordion para o Pequenino

O WeekDaysAccordion pressupõe que o usuário sabe ler labels de dias da semana (Seg, Ter, Qua…) e entende a estrutura de accordions. Para uma criança de 4-6 anos, isso são 2 barreiras cognitivas desnecessárias. A alternativa de lista plana com “missões de hoje” destaca é direta e não depende de leitura ou compreensão de UI pattern.

Por que exibir o progresso semanal de forma qualitativa (não %) para Pequenino e Explorador

Porcentagem é uma abstração que exige compreensão de frações e proporção — habilidades que se desenvolvem entre 8-10 anos (Piaget, Estágio Operatório Concreto). Para o Pequenino (4-6), usar porcentagem é pedagogicamente incorreto. Para o Explorador (7-9), é limítrofe — preferimos a representação de jornada que é autoexplicativa.

Por que o Aventureiro usa XP numérico

A faixa 10-12 anos já tem senso numérico consolidado e se identifica com a linguagem de jogos. “420/500 XP” é mais motivador que “84% da meta” porque XP tem conotação de progressão acumulada, não de porcentagem de uma obrigação.

Por que as Estrelas de Coragem são sempre ao final da tela

Colocar as Estrelas de Coragem acima da meta semanal criaria a impressão de que contribuem para a meta — o comportamento que o Comitê Pedagógico explicitamente proibiu. Posicionadas ao final, após um divisor visual claro, elas comunicam: “isso é uma coisa diferente e especial, não é sobre pontos”.

Questões em aberto para o comitê avaliar

  1. Fórmula de nível para o Aventureiro: linear (100 XP = 1 nível) ou curva? Uma curva logarítmica faz os primeiros níveis subirem rápido (motivação inicial) e depois desacelera (retenção a longo prazo). Isso é uma decisão de produto, não apenas de UX.

  2. Streak punitivo vs. streak motivacional: o P1-02 sugere streak mas sem punição por quebra. Como o app comunica a quebra de streak para o Aventureiro e Pro sem criar ansiedade? O Comitê Pedagógico proibiu streak punitivo — este documento não especifica o comportamento de “streak quebrado”. Aguarda orientação.

  3. Recompensa visual para crianças sem meta configurada: se o pai não configurou recompensa semanal, o componente RewardPreview exibe o quê? Estado vazio com nudge para o pai? Ou oculto por completo?

  4. WeekDaysAccordion para Explorador: o accordion de dias pode ser confuso se a criança só tem tarefas num dia mas vê 7 abas. Alternativa: exibir apenas os dias com tarefas. Tradeoff com a orientação temporal (a criança precisa saber que amanhã tem tarefa?).
